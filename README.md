# ArriveMate

ArriveMate 是一个面向 Robotaxi 后排智能座舱的 AI Agent Web Demo。

项目目标是验证一个 Robotaxi 座舱 AI 产品方向：

> 将 Robotaxi 车程转化为“到达前准备空间”，让乘客在抵达目的地前完成信息准备、状态调整、行动提醒和座舱环境切换。

在线体验：

[https://robotaxi-arrivemate.netlify.app](https://robotaxi-arrivemate.netlify.app)

## 项目背景

Robotaxi 与普通网约车相比，车内体验发生了关键变化：司机从服务链路中消失，乘客不再依赖司机完成路线确认、安全感建立、临时提醒、环境调节和轻量问询。

这让座舱 AI Agent 不应只承担“车控助手”或“智能客服”的角色。它更有价值的机会，是在无人驾驶车程中主动理解乘客到达后的任务，并把车内时间转化为可被利用的准备空间。

ArriveMate 因此聚焦一个明确命题：

- 用户上车后，AI 主动欢迎并确认行程状态
- AI 主动询问用户到达后要做什么
- AI 根据目的、状态和剩余车程生成到达前准备计划
- 用户确认后，AI 联动座舱状态并在到达前完成收口提醒

## 需求与场景分析

### Robotaxi 座舱的新需求

无人驾驶座舱中，乘客会产生几类新的需求：

- **确定性需求**：知道目的地、ETA、自动驾驶状态、安全状态是否正常。
- **安全感需求**：没有司机后，需要一个可信的座舱角色解释当前状态。
- **到达前准备需求**：面试、赶飞机、开会、休息等场景都需要抵达前的最后整理。
- **低操作需求**：后排大屏适合远距离浏览，不适合复杂手动输入。
- **环境联动需求**：灯光、音乐、座椅、温度和提醒方式应服务于具体出行目的。

### 为什么不是普通 Chatbot

ArriveMate 不以长聊天记录为核心。AI 对话只用于表达当前状态、理解结果、计划说明和提醒。真正的信息承载方式是大卡片、状态面板和明确的确认分支。

### 为什么不是普通车控助手

车控不是独立功能集合，而是到达前准备计划的一部分。例如：

- 面试准备需要柔和专注、音乐关闭、端正坐姿
- 机场准备需要明确提醒、降低音乐、突出 checklist
- 商务会议需要冷静专注、办公坐姿、简洁提醒
- 休息恢复需要暗光、低打扰、温和唤醒

## 核心场景

本期 Demo 收敛为 4 个 P0 场景：

| 场景 | 用户语音 | AI 核心识别 | 座舱联动 |
|---|---|---|---|
| 面试准备 | 我等会儿要去面试，有点紧张 | 面试、紧张、快速准备、稳定状态 | 柔和专注、音乐关闭、端正坐姿、轻声提醒 |
| 机场准备 | 我要去首都国际机场，帮我看下要注意什么 | 机场、时间敏感、证件行李、到达流程 | 明亮清醒、低音量、明确提醒 |
| 商务会议准备 | 我等会儿要参加客户会议，帮我整理一下状态 | 客户会议、需要专注、会议目标、表达重点 | 冷静专注、音乐关闭、办公坐姿、简洁提醒 |
| 休息恢复 | 我有点累，想在车上休息一下 | 疲惫、低打扰、到达前唤醒 | 暗光、白噪音、放松坐姿、轻柔唤醒 |

面试场景额外包含一个 mock 异常兜底：ETA 延误提示与 mock 通知文案。Demo 不会真实发送消息或变更路线。

## 功能说明

### 主流程

```text
boarding
→ agent_intro
→ asking_purpose
→ voice_input
→ understanding
→ intent_result
→ plan_confirm
→ executing
→ arrival_reminder
```

页面首次进入后，AI 会自动完成欢迎、能力介绍和主动询问。用户点击底部语音按钮后，流程会自动播放：

1. 展示用户语音文本
2. 展示 AI 正在理解
3. 展示结构化识别结果
4. 展示到达前准备计划
5. 等待用户确认

### 计划确认分支

计划生成后提供 3 个分支：

- **开启计划**：进入执行态，展示座舱状态前后变化。
- **调整计划**：展示当前场景的 2-3 个调整方向，选择后展示对应轻量计划。
- **暂不需要**：进入低打扰待命，但仍保留基础到达提醒能力。

执行态和低打扰待命态都会提供：

```text
模拟到达前提醒
```

点击后进入到达前提醒页，展示当前场景的 arrival reminder 和 checklist。

### 页面区域

Demo 页面分为 5 个固定区域：

| 区域 | 作用 |
|---|---|
| 顶部行程与安全状态栏 | 展示目的地、ETA、自动驾驶状态、安全状态、路线状态 |
| AI Agent 主交互区 | 展示 ArriveMate 话术、用户语音、当前 Agent 状态 |
| AI 决策与到达前准备区 | 展示识别结果、计划、确认分支、执行态、提醒态 |
| 座舱联动状态区 | 展示灯光、音乐、座椅、温度、提醒方式的前后变化 |
| 底部语音指令模拟区 | 通过 4 个按钮模拟语音输入 |

## 技术栈

- React
- Vite
- JavaScript
- CSS
- 前端 Mock Data
- Netlify 部署

项目不接入：

- 后端服务
- 数据库
- 真实 ASR/TTS
- 真实地图、路线、ETA API
- 真实车控 API
- 真实消息发送

所有行程、识别结果、AI 文案、座舱状态和提醒内容均来自本地 mock data。

## Demo 验收标准

- 页面能明显看出是 Robotaxi 后排横向大屏，而不是普通网页或聊天窗口。
- AI 会主动欢迎、介绍能力并询问用户到达后任务。
- 4 个语音场景均可点击并跑通核心流程。
- AI 能展示用户意图识别、准备计划和确认分支。
- 开启计划后能展示座舱状态前后变化。
- 调整计划分支为一次性轻量 mock，不进入多轮编辑。
- 暂不需要分支进入低打扰待命，并仍可触发基础到达提醒。
- 到达前提醒页能展示 checklist 和收口提醒。
